Noxiouse Engine Documentation

Welcome to the official documentation for Noxiouse Engine — a modern C++20 / Vulkan 1.4 / .NET 9 3D game engine and editor built around a bindless GPU-driven visibility-buffer renderer, a frame-compiled Render Graph, decoupled hardware Ray Tracing & ReSTIR, Large World Coordinates (64-bit double), World Partition & HLOD streaming, Jolt 3D / Box2D v3 physics, Skeletal Animation Graphs & Sequencer, and C# Hot-Reload Scripting.

High-Level Engine Architecture

Noxiouse is organized into four build targets plus a sample game project:

Target / Folder Type Files Plain-English Purpose
NoxCore/ Static Library (C++20) 295 The core engine: NRI graphics abstraction, Vulkan 1.4 backend, frame-compiled RenderGraph, hybrid visibility-buffer + RT + path-traced Renderer, Scene ECS (47 components), Asset cooking & streaming pipeline, Physics (Jolt 3D + Box2D 2D), Animation & NodeGraph, Scripting (.NET 9 / Coral), Tasks (JobSystem), and Profiling.
NoxScriptCore/ Managed Class Library (C# / net9.0) 28 The Nox C# API (Nox.ScriptCore.dll) providing EntityBehaviour, Entity, component wrappers, Physics, Mesh / MeshBuilder, Jobs, Scene, Input, WorldUnits, and Vector3d.
NoxEditor/ Executable (C++20) + Shaders 31 C++ + 113 Shaders The full authoring environment with multi-viewport layout, gizmos, Undo/Redo, 12 specialized panels (including Levels), and 1-click .npak Game Packager. Also houses all 113 Slang/HLSL shaders in NoxEditor/assets/shaders/.
NoxRuntime/ Executable (C++20) 3 The lightweight shipping game player that mounts a cooked .npak archive, boots the startup scene in RuntimeAssetManager read-only mode, and runs the game loop without editor overhead.
Facerun/ Sample Project (.nproj + C#) 18 A playable testbed project showcasing character controllers, weapons/projectiles, multithreaded voxel terrain generation, additive level streaming, and World Partition streaming.

Six Golden Architectural Rules

  1. Zero Graphics API Leak: Vulkan headers (vulkan.hpp, vk_mem_alloc.h, NVIDIA Streamline, NRD) live strictly inside NoxCore/src/NRI/Vulkan/. The rest of the engine talks exclusively to abstract NRI::* interfaces.
  2. 100% Bindless (VK_EXT_descriptor_heap): No VkDescriptorSets exist in engine rendering code. All textures, storage image mips, buffers, Acceleration Structures, and samplers live in a persistently mapped descriptor heap buffer indexed by uint32_t slot IDs, while buffers are accessed via 64-bit BufferDeviceAddress (BDA) pointers pushed via vkCmdPushDataEXT.
  3. Unified Image Layouts (VK_KHR_unified_image_layouts): Every GPU texture is transitioned to VK_IMAGE_LAYOUT_GENERAL once upon creation or upload and remains in GENERAL for its entire lifetime. Synchronization uses pure execution/memory stage+access masks (VkMemoryBarrier2).
  4. Reverse-Z Projection: Near plane is mapped to 1.0 and far plane / infinity to 0.0, paired with floating-point depth (D32_SFLOAT) and CompareOp::Greater or GreaterOrEqual for superior depth precision at kilometer distances.
  5. Large World Coordinates (LWC): Entity world translations (TransformComponent::Translation, WorldTransformComponent::WorldPosition) are stored in 64-bit glm::dvec3 (double). Before uploading to the GPU, the renderer subtracts the camera's glm::dvec3 world position on the CPU so every shader operates in high-precision camera-relative float space.
  6. Declarative Render Graph: Every GPU pass is registered via RenderGraph::AddPass(name, flags, setup, execute). The graph automatically culls unused passes, schedules Async Compute queues, aliases transient VRAM, synthesizes exact Synchronization2 barriers, and records command buffers in parallel across worker threads.

Complete Frame Lifecycle (Step-by-Step)

Step 1
Window & Input Poll
SDL3 polls OS window/keyboard/mouse events, updates relative mouse deltas, and checks swapchain resize.
Step 2
Async Streaming Tick
AssetLoader::Update & TextureStreamer::Update process cooked textures and mesh pages within a shared 64 MB/frame upload budget.
Step 3
Sequencer & C# Update
Scene evaluates TimelinePlayerComponent tracks (11 track types) and invokes C# EntityBehaviour.OnUpdate(dt).
Step 4
Fixed 60 Hz Physics
Runs C# OnFixedUpdate(1/60s), steps Box2D v3 (2D) & Jolt (3D LWC double-precision), and interpolates PhysicsPoseComponent.
Step 5
Parallel Animations
Evaluates Animators & 11-node AnimationGraphs across JobSystem workers, fires Notifies, and extracts Root Motion.
Step 6
Late Update & Transforms
Updates BoneSockets, runs C# OnLateUpdate(dt), and propagates WorldTransformComponent in parallel via SceneGraph.
Step 7
World & GPU Scene Sync
Ticks CPU Particles, Level Streaming, and WorldPartition cells, then incrementally patches dirty instances into GpuScene.
Step 8
RenderGraph Compile & Run
Compiles 40+ passes (Culling, Visibility Buffer, G-Buffer, RT/GI/ReSTIR/PathTracer, Deferred Lighting, DLSS/TAA, Post), aliases VRAM, and records Vulkan command buffers across worker threads.
